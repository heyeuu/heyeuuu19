## 1. 模型量化在解决什么问题？

随着模型规模增大，推理瓶颈往往会从计算能力转向内存与带宽：

- 模型参数无法完整驻留在目标设备内存中
- 数据搬运成本上升，访存成为主要开销
- 延迟、功耗和部署成本难以满足要求

量化通常带来以下收益：

- **降低模型体积**：FP32 -> INT8 在存储层面理论上可减少约 75%。
- **提升推理效率**：在支持低精度算子的硬件上，整数计算通常有更高吞吐。
- **降低能耗与成本**：数据搬运量减少，计算精度降低，整体资源消耗下降。

## 2. 量化的本质：浮点和整数之间的映射

常见形式是线性仿射量化（Affine Quantization）：

$$
R = S \times (Q - Z)
$$

- $R$：浮点值（Real）
- $Q$：量化整数（Quantized）
- $S$：缩放因子（Scale）
- $Z$：零点（Zero-point）

对应的量化公式为：

$$
Q = \text{round}\left(\frac{R}{S} + Z\right)
$$

反量化公式为：

$$
R' = S \times (Q - Z)
$$

由于存在 `round` 取整，量化会引入误差（即 $R' \neq R$）。

## 3. 量化选型的四个关键维度

### 3.1 对称量化 vs 非对称量化

- **对称量化**：通常令 $Z=0$。实现相对简单，推理时零点处理开销较低。
- **非对称量化**：$Z$ 可以不为 0。对偏移分布的数据，整数区间利用率通常更高。

实践中常见做法：

- 权重常采用对称量化（权重分布通常更接近以 0 为中心）。
- 激活常采用非对称量化（例如 ReLU 后分布通常偏向正区间）。

#### 💡 直观演示：一个非对称量化的最小例子

设激活统计范围为：$R_{min}=-2.0$，$R_{max}=6.0$，量化到 UINT8（$Q_{min}=0$，$Q_{max}=255$）。

第一步：计算缩放因子 $S$

$$
S = \frac{R_{max}-R_{min}}{Q_{max}-Q_{min}} = \frac{6.0 - (-2.0)}{255 - 0} = \frac{8}{255} \approx 0.03137
$$

第二步：计算零点 $Z$

$$
Z = \text{round}\left(Q_{min} - \frac{R_{min}}{S}\right) = \text{round}\left(0 - \frac{-2.0}{0.03137}\right) = \text{round}(63.75) = 64
$$

由于 $Z=64 \neq 0$，该示例属于非对称量化。

第三步：量化浮点值 $R=3.0$

$$
Q = \text{round}\left(\frac{3.0}{S} + 64\right) = \text{round}(95.6 + 64) = \text{round}(159.6) = 160
$$

第四步：反量化并计算误差

$$
R' = S \times (160 - 64) \approx 0.03137 \times 96 \approx 3.0117
$$

可见原值 3.0 反量化后约为 3.0117，误差约 0.0117。

### 3.2 量化颗粒度（Granularity）

- **Per-Tensor**：整个张量共享一组 $(S, Z)$。实现简单、开销低，但更易受离群点影响。
- **Per-Channel**：每个通道独立使用 $(S, Z)$。通常精度更稳定，是权重量化中的常见方案。
- **Per-Group**：在通道维进一步分组量化，常用于 INT4（例如 group size 为 64 或 128）。

经验上，比特宽度越低，越需要更细的量化颗粒度（Per-Channel / Per-Group）。

### 3.3 量化对象

- **Weight-Only**：仅量化权重，激活保持 FP16/BF16。
- **W8A8**：权重和激活均量化为 INT8。

常见路径：

- LLM 常从 Weight-Only（如 W4A16、W8A16）开始。
- 一些规模较小的 CV/NLP 模型常使用 W8A8。

### 3.4 比特宽度

- **INT8**：精度与工程可用性通常较均衡。
- **INT4**：压缩率更高，但误差控制与工程实现难度明显上升。
- **INT2 及更低**：通常需要专门训练策略和硬件支持，不常作为通用起点。

## 4. 两条路线：PTQ 和 QAT

### 4.1 PTQ（Post-Training Quantization）

PTQ 的基本思路是：保留已有的高精度模型参数，不再进行完整训练，而是在部署前完成量化参数的估计与图转换。

典型工程流程通常包括以下步骤：

1. **确定量化目标**：例如 W8A8、W8A16 或 Weight-Only（如 W4A16），并确认目标硬件支持的算子类型。
2. **准备校准集**：选择与线上分布接近的数据样本，用于估计激活范围。样本量通常远小于训练集，但需要覆盖主要输入模式。
3. **统计激活分布**：在浮点模型上插入 Observer（统计器），收集各层激活的范围或直方图信息。
4. **求解量化参数**：根据策略计算每层/每通道的 $S$ 与 $Z$，并确定是否做截断（clipping）。
5. **图优化与导出**：融合可融合算子（如 Conv+BN+ReLU），插入 Quant/DeQuant 或替换为低精度内核。
6. **离线评估**：同时检查精度、延迟、吞吐、显存占用和端到端稳定性。

PTQ 常见形态：

- **动态量化（Dynamic）**：激活的 $S$、$Z$ 在推理时按输入动态估计；改造成本低，但运行期开销更高。
- **静态量化（Static）**：离线确定激活范围；推理路径更固定，通常性能更稳定。
- **Weight-Only PTQ**：仅量化权重，激活保持 FP16/BF16；在 LLM 场景中更容易先落地。

常见校准策略：

- **Min-Max**：实现简单，但容易被少量离群值主导。
- **Percentile**：截断高百分位极值，通常在稳健性上优于 Min-Max。
- **KL Divergence**：通过分布匹配选择阈值，计算成本更高但常用于高精度场景。

PTQ 的主要优势是迭代快、工程改动小；主要风险是分布偏移和低比特敏感层导致的精度下降。

### 4.2 QAT（Quantization-Aware Training）

QAT 的核心是：在训练或微调阶段显式模拟量化误差，使模型参数在优化过程中主动适应整数近似带来的扰动。

QAT 的计算机制通常是：

- **前向传播**：在关键节点执行 Fake Quant（含截断、舍入、反量化），让前向数值接近真实量化路径。
- **反向传播**：通过 STE（Straight-Through Estimator）近似处理不可导的舍入操作。
- **参数调度**：训练早期可先稳定主干参数，再逐步冻结 Observer 或量化参数，减少训练振荡。

常见训练流程：

1. **从预训练模型初始化**：通常先从 FP32/FP16 已收敛模型出发，而不是从头训练。
2. **插入 Fake Quant 节点**：按部署目标确定量化位置、比特宽度和颗粒度。
3. **短周期微调**：用较小学习率继续训练，重点恢复精度敏感层。
4. **冻结与导出**：固定量化参数后导出部署图，并在真实推理后端复测。

QAT 的典型收益是低比特（尤其 INT4/INT2）下精度显著优于 PTQ；代价是训练资源、工程复杂度和实验周期明显上升。

实践上可按以下顺序决策：先做 PTQ 验证收益，再对关键模型或关键任务投入 QAT。

## 5. LLM 时代为什么 W4A16 常见？

LLM 自回归解码阶段通常表现为 Memory-bound：每个 token 的生成过程中，访存开销常高于计算开销。

- 将权重从 FP16 压缩到 INT4，可显著降低带宽压力。
- 激活保持 FP16/BF16，可在一定程度上降低精度风险，并减少额外动态量化处理开销。

因此，Weight-Only（如 W4A16）成为线上和本地 LLM 推理中的常见起点。

LLM 量化中的常见进阶方法：

- **SmoothQuant**：通过等价变换缓解激活离群点问题，支持更稳定的 W8A8。
- **GPTQ**：利用二阶信息进行误差补偿，常用于 4-bit PTQ。
- **AWQ**：优先保护关键权重通道，在效率和精度间取得平衡。

## 6. 可执行的落地流程（推荐）

1. **建立基线**：记录 FP16/BF16 下的准确率、延迟、吞吐和显存占用。
2. **初步验证**：先尝试 PTQ INT8，或在 LLM 场景尝试 Weight-Only W8A16，评估收益与精度。
3. **策略调优**：当精度不足时，优先调整颗粒度与校准策略（如 Per-Channel + Percentile/KL）。
4. **进一步压缩**：若带宽/显存仍受限，可评估 GPTQ/AWQ 下的 W4A16。
5. **升级路线**：若 PTQ 难以满足目标，再评估投入 QAT。

## 7. 常见误区

- **“只要量化就一定更快”**：若硬件不支持高效低精度指令，或 Quant/DeQuant 节点无法融合，量化后可能反而变慢。
- **“PTQ 校准集可以随意选”**：静态量化高度依赖校准分布；校准数据与线上数据偏差大时，精度可能显著下降。
- **“比特越低越好”**：在缺乏硬件和算子支持时，极低比特可能只降低存储占用，实际推理效率未必改善。
- **“只看权重不看激活离群点”**：LLM 中激活离群点会显著影响激活量化效果，忽略该问题常导致 W8A8 不稳定。
